# 設計決策紀錄

日期格式 YYYY-MM-DD。每條決策註明來源：**規格**（原始需求文件）、**使用者**（2026-10-21 問答確認）、**技術**（開發者自行決定的一般技術細節）。

## 計算規則

| # | 決策 | 來源 |
|---|------|------|
| C1 | 本月總花費 = 信用卡變動消費合計 + 已確認固定支出合計 + 額外消費合計 | 規格 4.3 |
| C2 | 信用卡變動消費 = 該卡當月原始總額 − 已確認、付款來源為該卡、包含於卡片總額、實際扣款日在該月的固定支出 | 規格 3.1／4.2 |
| C3 | 刷卡付的固定支出確認時，**預設自動視為包含在該卡月總額內**；罕見例外在進階選項取消勾選 | 使用者 |
| C4 | 退款與分期不另外建模，**照銀行 App 的日曆月總額填寫**；總額可為負數，標示「需留意」 | 使用者 |
| C5 | 「未輸入」與「已確認為零」嚴格區分：`amount = null` vs `amount = 0` | 規格 4.4 |
| C6 | 扣除後變動消費為負數時標示異常並列出明細，不截斷為 0 | 規格 4.4／14.8 |
| C7 | 所有衍生金額即時計算，不存資料庫 | 規格 7.3／13 |

## 固定支出

| # | 決策 | 來源 |
|---|------|------|
| F1 | 到期月份自動顯示「待確認」，確認後才計入，計入**實際扣款日所在月份** | 使用者（採用規格 8.5 建議） |
| F2 | 「待確認」不存資料庫，依週期即時推算；資料庫只存使用者動過的期數（已確認／本期未扣款／延後），唯一鍵 `[templateId+periodKey]`，結構上不可能重複產生同一期 | 技術 |
| F3 | 延後的期數在之後每個月持續顯示「待確認（N 月期）」直到確認或標記未扣款；延後不移動後續週期 | 使用者 |
| F4 | 只有**單筆**一鍵確認（依預設金額、來源、日期），沒有整批確認 | 使用者 |
| F5 | 不固定週期項目每月都列出（淡色「不定期·本月無」），點進去記錄；不會變成待確認，不影響完整性 | 使用者 |
| F6 | 每個項目有「追蹤起始月份 startYm」與「週期基準 anchorYm」分開存：基準決定哪幾個月到期，起始月份之前不算到期（避免回溯好幾年的舊期數全部變成待確認） | 使用者（Q3）＋技術 |

## 技術

| # | 決策 | 理由 |
|---|------|------|
| T1 | 套件版本固定在支援 Node 20 的範圍（vitest 4.1、jsdom 27、TypeScript 5.9） | 本機 Node 20.19.5；vitest 5／jsdom 30 需 Node 22 |
| T2 | HashRouter | GitHub Pages 無伺服器改寫，子頁重新整理不會 404 |
| T3 | IndexedDB 名稱 `homeexpense-tw-v1`；Service Worker scope = 部署子路徑 | 與其他網站／專案隔離 |
| T4 | SW 採 prompt 更新模式，使用者按「重新整理」才換版 | 避免輸入途中被換版打斷 |
| T5 | `BASE_PATH` 格式不對時中止建置 | Windows Git Bash 會把 `/HomeExpense/` 改寫成 `C:/Program Files/Git/HomeExpense/` |
| T6 | ID 用 UUID v4；`crypto.randomUUID` 不可用時（區網 http 測試）退回 `getRandomValues` | 穩定 ID、離線產生 |
| T7 | 所有日期／月份以本地字串 `YYYY-MM-DD`／`YYYY-MM` 處理，不經過 UTC | 避免跨日、跨月錯誤 |
| T8 | 版控：本機 git，`main`（正式）＋`branch`（開發），不推送 | 使用者 |
